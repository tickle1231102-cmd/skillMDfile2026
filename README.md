# skillMDfile2026

웹 기반 AI 서비스를 만들다 보면, 출시 직전마다 같은 불안이 반복됩니다. 비밀값이 코드에 숨어 있지 않은지, 프론트만 믿고 가격이나 권한을 넘기고 있지 않은지, Supabase의 RLS가 진짜로 켜져 있는지, 로그인이 필요한 데이터가 다른 사람에게 새지 않는지, 무료 티어 한도를 넘기기 직전인지 같은 것들입니다.

이 저장소의 스킬은 그 반복되는 확인 작업을 한 번에 묶기 위해 만들었습니다. 막연한 보안 감각이 아니라, 실제 코드와 설정, 배포 환경을 보고 출시 전 점검을 같은 방식으로 다시 돌릴 수 있게 하는 것이 목적입니다.

## 무엇이 불편했나

- 출시할 때마다 보안 체크 항목을 새로 떠올려야 했다.
- 같은 질문을 여러 번 하다 보면 빠뜨리는 항목이 생겼다.
- “프론트에서 막았으니 괜찮다”는 착각이 자주 남았다.
- Supabase, 결제, API, AI 기능, 배포 설정이 각각 따로 놀아 한 번에 보기 어려웠다.
- 문제가 있어도 어디까지가 차단 사유인지, 무엇부터 고쳐야 하는지 정리하기 힘들었다.

## 이 스킬이 없앤 것

이 스킬은 출시 전 보안 점검을 체크리스트로 고정합니다. 매번 기억에 의존하지 않고, 아래를 같은 기준으로 다시 확인하게 합니다.

- 비밀값을 코드에 박아 넣지 않았는지
- 가격, 수량, 권한, 결제 상태를 서버에서 다시 검증하는지
- Supabase를 쓴다면 RLS와 정책이 실제로 걸려 있는지
- 로그인이 필요한 데이터에 인가 검사가 들어가는지
- rate limit, 입력 검증, XSS/SSRF, 웹훅 서명 검증이 빠지지 않았는지
- 무료 티어 한도와 요금 알림을 확인했는지

점검 결과도 단순히 통과/실패로 끝내지 않습니다. 무엇이 위험한지, 어디를 고쳐야 하는지, 출시를 막아야 하는지까지 한 번에 보이게 정리합니다.

## 언제 쓰나

- 새 AI 서비스의 첫 출시 직전
- Supabase, 결제, 업로드, 관리자 기능을 붙인 뒤
- 외부 API나 LLM 호출이 늘어났을 때
- “이 정도면 괜찮나?” 싶은데 손에 잡히는 기준이 필요할 때

## 한 줄 요약

이 스킬은 출시 직전의 애매한 불안을, 다시 돌릴 수 있는 보안 점검 절차로 바꿉니다.
